   days, and Horizons' ephemeris for this object is that TLE. So the required-disagreement gate runs

   *Rule-4 report and ruling, 2026-09-29.* Spacetrack Report #3 is pinned; Vallado et al. 2006,
   cited since L1 without a hash, is now pinned too. Its verification set — `SGP4-VER.TLE` and the
   expected TEME ephemerides — ships with the authors' own distribution, whose stated terms are
   that "there is no license associated with the code and you may use it for any purpose". **The
   test vectors come from that distribution**, under a stated-grant licence identifier quoted from
   its raw text, not from a later repository whose top-level licence is AGPL with a carve-out;
   the reference code stays unopened, as D4 and the `eclips.f` precedent say. The verification
   file's trailing fields are read from the paper's own description of the file, then checked
   against the ephemerides. **T-01's band is fixed before the comparison runs**: the predicted
   size and direction of the difference, from the two frame models at the capture's own epochs
   and the named smaller contributions, are written and committed before Horizons' values are
   compared, and agreement below the band is the failure; the frozen 2.246 m is recorded beside
   the result. Which equation of the paper the GMST polynomial is, is settled from the paper.

   *Ruled 2026-09-29, on what "the papers" are.* Spacetrack Report #3 prints its equations and its
   FORTRAN interleaved, statement by statement; there is no equations-only form of the 1980
   algorithm, and Vallado et al. 2006 is a paper of corrections against it. Unlike `eclips.f` — a
   secondary implementation of laws published elsewhere, under an unestablished licence — the
   report's FORTRAN is the **primary specification**, a public-domain government report's own, and
   SGP4 is defined by what its code does, so under §4 rule 8 it is normative, not a template to
   avoid. The port follows the report — equations and code together — with every correction the
   2006 paper's text describes applied, written in this tree's own language and constraints, the
   arithmetic order kept where the verification vectors depend on it. **Independence comes from
   the other side:** the verification ephemerides were produced by the 2006 authors' own code, so
   that code stays unopened, and the vectors test whether the port applied the corrections
   rather than repeating whatever that code does. If every correction the paper describes is
   applied and a case still misses the vectors' tolerance, the residual is reported per case
   before anything else is opened.
